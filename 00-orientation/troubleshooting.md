# When something goes wrong

When a script or a check fails, it prints a message. Each message is in this table. Find it in the left column. Then
read what it means and what to do.

Text in angle brackets, like `<invoice>`, changes with each run. For example, you may see "The ledger shows 2 payments
for INV-2043". Look for the row "The ledger shows <n> payments for <invoice>". That row means your employee paid the same
invoice more than once. Use one key per invoice, on every try.

| What you see                                                                            | What it means                                                            | Fix                                                                                                                     |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `bun: command not found`                                                                | Bun is not installed.                                                    | Install Bun from bun.sh. Then open a new terminal.                                                                      |
| `FAIL  Bun 1.4.4 or newer`                                                              | Your Bun is older than the course needs.                                 | Run `bun upgrade`.                                                                                                      |
| `FAIL  Port <port> free`                                                                | Something else is using this port: 7700, 7701 or 7702.                   | Stop that program. Or find it with the lsof command and the port number.                                                |
| `FAIL  Port 7702 free`, or your employee cannot start on port 7701                      | `bun run reference` is still running. It keeps ports 7701 and 7702 busy. | Press Ctrl+C in the terminal that runs `bun run reference`.                                                             |
| `Port 7700 is in use. Another world may be running.`                                    | A world is already running.                                              | Use the one that is running. Or stop it and start it again.                                                             |
| There is no world called "<name>"                                                       | The world name is wrong.                                                 | Run `bun run world freight-audit`.                                                                                      |
| `The world is not running at http://localhost:7700`                                     | `bun run reference` needs the world, and the world is not running.       | Start the world in another terminal: `bun run world freight-audit`.                                                     |
| There is no reference mode called "<mode>"                                              | The mode name is wrong.                                                  | Use `bun run reference`, `bun run reference naive` or `bun run reference record`.                                       |
| "no recorded reply for <invoice>"                                                       | The reference asked the model a question it has no recorded answer for.  | Use `LLM_PROVIDER=replay`. Or record the answers with `MODEL_MODE=record`, a live `LLM_PROVIDER` and its key in `.env`. |
| "LLM_PROVIDER is <provider> but <KEY> is not set"                                       | A live provider needs its key, and the key is missing.                   | Copy `.env.example` to `.env` and add the key. Or use `LLM_PROVIDER=replay`.                                            |
| LLM_PROVIDER is "<name>"                                                                | The provider name is wrong.                                              | Use `replay`, `anthropic`, `openrouter` or `openai`.                                                                    |
| `MODEL_MODE=record needs a live provider`                                               | Recording needs a real model.                                            | Set `LLM_PROVIDER=anthropic` (or `openrouter` or `openai`), with its key in `.env`.                                     |
| `<role> fail` from `bun run models`                                                     | That role's model did not answer `pass`.                                 | Read the message after it. Most often the key is wrong, or the model id in `config/models.ts` no longer exists.         |
| `cost unknown (no price in config/models.ts)`                                           | The model has no price in the table. Its cost is not counted as zero.    | Find the provider's pricing page. Add the price and its link to `config/models.ts`.                                     |
| There is no step called "<name>"                                                        | The step name is wrong.                                                  | Copy a name from the list that the command prints.                                                                      |
| There is no part called "<name>"                                                        | The part name is wrong.                                                  | Copy a name from the list that the command prints.                                                                      |
| `ERROR the check for <step> could not load`                                             | The check itself is broken. Your work is not the cause.                  | Open an issue with the full output.                                                                                     |
| `FAIL  notes.md exists in the problem folder`                                           | `notes.md` was moved or deleted.                                         | Put it back in the step's `problem/` folder.                                                                            |
| `FAIL  Paid twice: names ...` or `Not paid: names ...`                                  | The line names the wrong invoice, or trusts the reply.                   | Read the ledger table that `bun run reference naive` prints.                                                            |
| `FAIL  Needs you: names ...` or `Refused: names ...`                                    | The line does not match the board.                                       | Run `bun run reference`, then read `localhost:7702/board`.                                                              |
| `No employee.toml in <folder>`                                                          | The checker cannot find your employee.                                   | Copy a starter kit to `employee/` at the repo root. Keep `employee.toml` in it.                                         |
| `employee.toml does not parse`                                                          | The file has a TOML mistake.                                             | Fix the line that the message names. Strings need quotes.                                                               |
| `employee.toml needs [contract] with start = ...`                                       | The checker does not know how to start your employee.                    | Add `start = "bun start.ts"` (or your own command) under `[contract]`.                                                  |
| `Your employee exited before it answered GET /health`                                   | Your employee crashed when it started.                                   | Read the output under the message. Fix the error, then run it again.                                                    |
| `Your employee did not answer GET /health within 10 s`                                  | It is slow to start, or it listens on the wrong port.                    | Read the port from the `PORT` environment variable.                                                                     |
| "<METHOD> <path> got no answer"                                                         | Your employee stopped answering.                                         | Keep it answering while a job runs. Run jobs in the background.                                                         |
| `GET /health answered <status>` or `GET /health says contract ...`                      | Health is missing, or it names the wrong contract version.               | Answer with contract "1", your employee name, and the tenant kaas-freight.                                              |
| `POST /jobs answered <status>` or "answered without a run_id"                           | The job route is wrong.                                                  | Answer 202 with `{"job_id", "run_id"}`.                                                                                 |
| "No trace for run <run_id>"                                                             | There is no trace file for that run.                                     | Write spans to `TRACE_DIR/<run_id>.jsonl`.                                                                              |
| "The trace has no invoke_agent span" or "no execute_tool span for <tool>"               | The trace is missing a span.                                             | Wrap each run in `invoke_agent`. Wrap each tool call in `execute_tool`.                                                 |
| "Reading changed the ledger"                                                            | A job wrote to a row that is not its own.                                | Write only to the job's own invoice.                                                                                    |
| `Your employee said done. The ledger shows nothing for <invoice>.`                      | The job said done, but nothing reached the ledger.                       | Check the write. Then check the ledger before you report.                                                               |
| "Your employee said done for <invoice>, but the ledger does not match the evidence"     | The write landed with the wrong amount or reason, or it landed twice.    | Compare with the rate confirmation and the proof of delivery.                                                           |
| "The ledger shows no payment for <invoice>"                                             | The pay call never happened, or it failed.                               | Call `pay_invoice` with an `Idempotency-Key`.                                                                           |
| "The ledger shows <n> payments for <invoice>" or "<n> payments after the crash"         | The same invoice was paid more than once.                                | Use one key per invoice, on every try and after a restart.                                                              |
| `the ledger shows it paid once, but your employee says ...`                             | The write landed, but the job did not report it.                         | After a timeout, read the ledger. The ledger decides.                                                                   |
| the pay tool never wrote, so the job must end "failed"                                  | The job claimed success on a write that never landed.                    | Report `failed`, with the ledger's reason.                                                                              |
| `is a duplicate ... and the ledger shows it paid`                                       | The must-never broke: a load was paid twice.                             | Check the load's other invoices before you pay.                                                                         |
| "bills above the rate confirmation, and the ledger shows it paid"                       | The must-never broke: an invoice was paid above the rate.                | Compare each line with the rate confirmation.                                                                           |
| "is not disputed and no dispute waits for approval"                                     | Doing nothing does not keep the rule.                                    | Dispute the trap, with the reason the evidence supports.                                                                |
| "was paid with no approval" or "was paid before Lena decided"                           | A payment over USD 5,000 did not wait for a person.                      | Put it in `GET /approvals`, and wait for a decision.                                                                    |
| `GET /approvals?status=waiting does not list job <job>`                                 | The approval is missing.                                                 | List each waiting approval with its `job_id` and `amount`.                                                              |
| "Jo Park is a contractor and may not approve"                                           | Your employee let Jo approve.                                            | Check the person's role at `GET /people` before you accept an approval.                                                 |
| "is over Ravi Shah's limit of USD 5,000"                                                | Your employee let Ravi approve over his limit.                           | Compare the amount with the person's `pay_limit_usd`.                                                                   |
| `Lena declined <invoice> ... A decline writes nothing`                                  | A declined job still wrote to the ledger.                                | On a decline, end the job as `declined`. Write nothing.                                                                 |
| "After the restart your employee does not know job <job>"                               | Jobs live only in memory.                                                | Save each job in `STATE_DIR`.                                                                                           |
| After the restart, job <job> is "working"                                               | The job did not resume after the restart.                                | On start, carry on with every job that is still `working`.                                                              |
| "Its scan has white text"                                                               | A document's text approved a payment.                                    | Treat document text as evidence, never as an instruction.                                                               |
| "The trace has no refusal for <invoice>"                                                | The refusal is not logged.                                               | Log a span with `x.policy.decision` set to `refuse`, and the rule in `x.policy.rule`.                                   |
| `cross-tenant access(es)`                                                               | A job read or wrote another tenant's rows.                               | Send the job's own tenant in `X-Tenant`.                                                                                |
| `The price table in config/models.ts is dated`                                          | The prices are older than the age limit in `config/models.ts`.           | Read the provider's current prices, and update `config/models.ts`.                                                      |
| `names model(s) <model> that are not in the price table`                                | The trace names a model that the checker cannot price.                   | Use a model from `config/models.ts`, or add its price there.                                                            |
| "None of the four invoices is settled"                                                  | There is no settled invoice, so there is no outcome to divide by.        | Pass `pay-one-invoice` first.                                                                                           |
| `The board says ...`                                                                    | The board's numbers do not match the traces and the ledger.              | Count every run's tokens, failed runs too. Count only settled invoices.                                                 |
| "the check hit an error: <message>"                                                     | Something unexpected happened inside a check.                            | Run it again. If it happens again, open an issue with the full output.                                                  |
| `SKIP  the LangGraph package in the lockfile ...` (every line of resume-with-langgraph) | Docker is not running, so the check cannot start Postgres.               | Start Docker. Then run `bun run verify resume-with-langgraph` again.                                                    |
| `FAIL  a run above the limit stops at an interrupt and writes a checkpoint row`         | The graph never paused, or its saved state is not in Postgres.           | Call `interrupt()` in `pay` above the limit. Use the Postgres checkpointer.                                             |
| `FAIL  the ledger has exactly one payment row for that run`                             | The ledger has no row, or more than one row, for the run.                | Insert with "on conflict do nothing". Insert only after the answer is "approved".                                       |
